# SQL and migration conventions

## Migrations

- **Append-only.** Never edit a merged migration. Correct it with a new one.
- Filenames: `YYYYMMDDHHMMSS_snake_case_description.sql` — generated by
  `./scripts/new-migration.sh`.
- **Idempotent DDL.** `create table if not exists`, `drop policy if exists`
  before `create policy`, `create or replace function`. CI rebuilds from zero
  every PR, so a migration that assumes prior state will fail there.
- One concern per migration. Schema, policies, and functions in separate files
  makes review and blame usable.
- Destructive changes get their own migration and an explicit note in the PR.

## Naming

| Thing | Convention | Example |
|-------|-----------|---------|
| Tables | plural snake_case | `request_items` |
| Columns | snake_case | `item_price_snapshot` |
| Timestamps | `<event>_at` | `completed_at` |
| Booleans | `is_<adjective>` | `is_visible` |
| Indexes | `<table>_<cols>_idx` | `requests_provider_status_seq_idx` |
| Unique indexes | `<table>_<cols>_uidx` | `requests_idempotency_uidx` |
| Policies | `<table>_<who>_<verb>` | `requests_receiver_read` |
| RPC params | `p_` prefix | `p_provider_id` |
| Local variables | `v_` prefix | `v_req` |

## Functions

Every mutating function must:

1. Be `security definer` — clients hold no write grant.
2. Pin `set search_path = public, pg_temp`. Unpinned definer functions are a
   privilege-escalation route, and `00_schema.test.sql` fails the build if one
   appears.
3. Re-check ownership itself. Definer rights are not a licence to skip the
   check.
4. Lock the row (`for no key update`) before validating a transition, so two
   concurrent callers cannot both pass the check.
5. Raise a bare code with `using errcode = 'P0001'`.
6. `revoke ... from public, anon` then `grant execute ... to authenticated`.

## Views

Views that must cross a tenancy boundary — joining `profiles` for a receiver
name, or counting rows the caller cannot read — run with **definer rights**
(`security_invoker = false`) and carry their **own** explicit predicate:

```sql
where pv.owner_id = auth.uid()      -- provider_queue, provider_archive
where r.receiver_id = auth.uid()    -- my_requests
```

Removing one of those predicates removes tenancy isolation entirely. If you
touch a view, re-read `02_rls_isolation.test.sql` first.

Views that need no such crossing should be `security_invoker = true` so base
table policies apply normally.

## Ordering

`requests.seq` comes from a single global sequence. Order is per-provider by
`seq` ascending among active rows. Gaps are expected and harmless.

Never store position. It is a window function over `seq` at read time, so it
cannot drift out of sync with reality.

## Timestamps

`timestamptz` everywhere, stored in UTC. Analytics bucket into
`Africa/Addis_Ababa` at query time. Never store local time.

## Money

`numeric(12,2)` with an explicit `currency` column defaulting to `ETB`. Never
floating point.
